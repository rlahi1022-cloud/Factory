## 0. 현재 상황 정리

### 보유 장비
- 종이박스 1개
- 집중광 랜턴 1개 (손전등 스타일)
- 흑백(Mono) 산업용 카메라 (Basler 추정, 정확한 모델 미확인)

### 촬영 대상
- 물병 (삼다수 페트병 대체 — 기획서 원안은 삼다수지만 다른 물병으로 진행)
- 확보 완료

### 결정 사항
- **1단계(빈 용기 검사)부터 시작** — 백라이트 조명 1개만 필요해서 현재 장비로 가능
- **2단계(조립 검사)는 나중** — 전면/측면 확산광 2개 이상 필요

## 1. 박스 터널 세팅

### 1-1. 박스 치수 확인

| 항목 | 권장값 | 이유 |
|---|---|---|
| 내부 길이 (조명–카메라 축) | **50cm 이상** | 산업용 카메라 최소 초점 거리 확보 + 확산 거리 확보 |
| 내부 폭 | 25cm 이상 | 병(지름 ~7cm) 주변 여유 |
| 내부 높이 | 25cm 이상 | 병(높이 ~20cm) 주변 여유 |

> 박스가 40cm 미만이면 더 큰 박스로 교체 권장.

### 1-2. 터널 뚫기

1. 박스를 눕혀 **긴 면이 조명–카메라 축**이 되게 배치
2. 마주보는 짧은 두 면에 구멍을 뚫음
   - **조명 쪽**: 랜턴 지름 + 1~2cm (예: 지름 6~7cm 원형)
   - **카메라 쪽**: 렌즈 지름 + 2~3cm
3. 두 구멍은 **완전히 일직선** (광축 일치)
4. 세로 위치는 짧은 면의 정중앙

> 자르기 전 연필로 먼저 표시 → 카메라·랜턴을 박스 바깥에 임시로 맞춰 광축 확인 → 그 다음에 자르기.

### 1-3. 내부 도배 (Light Trap)

- 재료: 검정 A4 용지, 검정 테이프, 검정 천 중 아무거나
- 내부 5면(위·아래·앞·뒤 + 옆 1면) 도배
- 겹치지 않게 붙임 (겹치면 층계 그림자 발생)
- 이음새 틈은 검정 매직으로 덧칠
- 완벽하지 않아도 OK, 80%면 충분

### 1-4. 병 지그 (임시)

- 박스 바닥, 조명–카메라 축 **정중앙**에 검정 테이프로 **작은 십자(+)** 마크
- 병 바닥 중앙이 교차점에 오도록
- 병 높이 조절 필요 시 종이컵을 뒤집어 받침대로 사용
- 의도적으로 1~2mm씩 다른 위치에 놓는 게 가이드의 '자연 편차' — 너무 고정하려 애쓸 필요 없음

### 1-5. 조명 고정 (집중광 핵심 대응)

**집중광 랜턴은 그대로 쓰면 hotspot(중앙만 밝음)이 생김 → 3가지 대응 병행**

#### ① 랜턴 고정
- 박스 **외부**에서 구멍을 향해 마스킹 테이프로 단단히 고정
- 높이 안 맞으면 책·상자로 받침대

#### ② 확산판 설치
- **복사용지 3~5장 겹치기** (1~2장은 부족)
- 박스 **내부**, 조명 구멍에서 **5~10cm 안쪽**에 위치
- 마분지로 간이 창틀 만들어 종이를 끼우면 교체 편리
- 모서리만 고정해서 중앙이 살짝 뜨게 (쭈글거리면 균질도 깨짐)

#### ③ 확산판–병 간격
- 최소 **10~20cm**
- 가까우면 병 한쪽만 밝고 반대쪽 어두운 hotspot 발생

#### 거리 배분 예시 (50cm 박스 기준)
```
[박스 외부: 랜턴] —5~10cm— [확산판] —10~20cm— [병] —30cm— [카메라]
```

#### 집중광 hotspot 검증 (필수)
- 병을 치우고 **확산판만** 촬영 (Pylon Viewer Live 모드)
- 화면 전체가 **고르게 하얗게** 보이면 성공
- 중앙만 유난히 밝으면 → 복사용지 추가 / 랜턴-확산판 거리 늘림
- **이 검증 없이 본촬영 들어가면 결함으로 오탐 발생**

### 1-6. 카메라 고정

**가장 중요**: 흔들림은 PatchCore 성능을 크게 깎음

- 삼각대 우선, 없으면 책·박스를 쌓아 받침대
- 본체를 마스킹 테이프로 **단단히** 고정
- 구멍과 렌즈 사이 틈은 검정 천으로 덮어 외부 광 차단
- Pylon Viewer Live로 보면서 병이 화면 정중앙, 프레임의 60~80% 차지하도록

## 2. Pylon Viewer 초기 세팅

> ⚠️ 메뉴 이름/위치는 Pylon Viewer 버전(6.x/7.x)과 카메라 모델에 따라 다를 수 있음. 못 찾으면 `Ctrl + F`로 파라미터 이름 검색.

### 2-1. 카메라 연결 & Pylon Viewer 실행

1. USB 카메라: USB 3.0 포트 **직접** 연결 (허브 X)
2. GigE 카메라: 이더넷 직결 + PC 네트워크 IP 대역 맞춤
3. Pylon Viewer 실행 → 좌측 `Devices` 패널에 카메라 인식 확인
4. 더블클릭 / `Open Device`로 연결 → 우측 `Features` 패널에서 설정

### 2-2. 핵심 파라미터 3가지 (필수)

| # | 파라미터 | 위치 | 설정값 | 이유 |
|---|---|---|---|---|
| ① | **Pixel Format** | Image Format Control | `Mono 8` | PatchCore 입력 호환, 처리 속도 확보 |
| ② | **Gain** | Analog Control | `0` | 노이즈 억제 — 밝기는 조명으로만 확보 |
| ③ | **Exposure Time** | Acquisition Control | `20000 µs` (=20ms) | 가이드 md 기준 병 정지 시 ~20ms |

**단위 확인**: 입력창 옆 단위가 `[µs]` 또는 `[ms]`. 헷갈리면 `20000` 입력 → 새까맣게 나오면 ms 단위였던 것 → `20` 재입력.

### 2-3. 부가 파라미터

| 파라미터 | 위치 | 설정값 | 이유 |
|---|---|---|---|
| Gamma | Analog Control | `1.0` 또는 Off | 선형 값 분포 유지 (PatchCore 원본 학습) |
| Trigger Mode | Acquisition Control → Trigger Selector=Frame Start | `Off` | 뷰어에서 직접 촬영, 나중에 Arduino 연동 시 On |
| Acquisition Frame Rate | Acquisition Control | 건드리지 않음 | 정지 촬영이라 무관 |
| AOI (Width/Height/Offset) | Image Format Control | 나중에 | 병 위치 확정 후 크롭 |

### 2-4. Live & 히스토그램 확인

1. 좌측 상단 `Continuous Shot` (▶) 클릭
2. `View → Image Window → Histogram` (또는 Tools 패널 `Histogram` 탭)

**목표 히스토그램 (1단계 빈 용기 기준)**

| 영역 | 목표 Gray Level | 판단 |
|---|---|---|
| 배경 (확산판 쪽) | 255 근처 포화 | ✓ 허용 |
| 병 영역 (내부·그림자) | **240 이하** | ✓ 디테일 보존 |
| 병 영역이 255 포화 | ✗ | Exposure 줄이거나 조명 낮춤 |

### 2-5. 저장 설정

- 포맷: **PNG** (무손실) 권장
- JPG는 압축 손실 → PatchCore 학습 부적합
- TIFF도 무손실이지만 파일 큼
- 경로는 임시 폴더(`C:/test_capture` 등) — 폴더 구조는 추후 확정

### 2-6. 플리커 체크

1. 세팅 고정 상태에서 `Single Shot` 5번 연속
2. 5장 눈으로 비교 → 눈에 띄는 밝기 출렁임 있으면 조명 문제
3. 정밀 체크는 나중에 Python `numpy.mean()` 으로 ±2% 이내 확인

**플리커 원인**
- AC 어댑터 LED: 60Hz 깜빡임 → Exposure를 16.67ms의 배수로 (20ms OK)
- 저가 LED 회로 문제 → 배터리 구동 LED로 교체

## 4. 촬영 계획 (1단계)

### 4-1. 대상 & 원칙

- 물병 고정 방향 — **PatchCore는 정렬된 이미지 전제, 회전 금지**
- 유통기한 인쇄면은 **카메라 반대쪽**으로 돌려 프레임에서 제외
- 조명: 백라이트 (투과광)

### 4-2. 수량 목표 (가이드 md 기준)

| 구분 | 수량 | 방법 |
|---|---|---|
| Normal | 150장 | 완전 정지 50 + 지그 유격 편차 50 + 밝기 미세 편차 50 |
| Defect Easy | ~20장 | 유성매직 낙서, 투명테이프 부착 |
| Defect Hard | ~20장 | 미세 실 조각, 얇은 스크래치 |

### 4-3. 학습 정책
- **Normal만** PatchCore 학습에 사용 (비지도 학습)
- Defect는 평가(검증)용
- 파일명/폴더 구조는 촬영 시작 전에 확정 필요 (다음 단계에서 설계)

## 6. 불확실한 부분 (솔직히 기록)

- **카메라 최소 초점 거리**: 렌즈 스펙에 따라 다름. 50cm가 부족할 수도, 여유로울 수도 있음. Live 모드에서 초점 안 맞으면 거리 늘릴 것.
- **집중광 광량 충분성**: 찍어봐야 앎. 너무 어두우면 Exposure 100ms 이상 필요할 수도 있는데, 1단계 정지 촬영은 OK, 이동 촬영은 불가능.
- **물병 엠보싱 영향**: 삼다수 대체 병이 매끈한 원통형인지 확인 필요. 엠보싱·굴곡 많으면 그림자가 복잡해져 PatchCore 오탐 유발 가능.
- **카메라 브랜드**: Basler 전제로 가이드 작성. Hikrobot·Daheng이면 전용 뷰어(MVS 등) 필요.
- **Pylon Viewer 메뉴명**: 버전·모델에 따라 달라질 수 있음. `Ctrl+F` 검색 활용.

## 7. 포트폴리오 관점의 가치 (참고)

### 7-1. 원칙 vs 재료

| 측면 | 평가 |
|---|---|
| **원칙(philosophy)** | 실제 공장과 거의 1:1 — Light Trap, 확산·편광, Mono8, Gain 0 등 업계 표준과 동일 |
| **재료(material)** | 프로토타입 등급 — 종이박스·랜턴·복사용지 (공장은 알루미늄 하우징·산업용 LED 바·오팔 확산판) |
| **시스템** | 부족한 부분 있음 — 인라인 속도, PLC/MES 연동, 캘리브레이션, 장기 드리프트 |

### 7-2. 면접 활용 멘트 (예시)

> "종이박스로 시작했지만 Light Trap, 편광 배치, Gain=0 / 조명 광량으로 밝기 제어 같은 원칙은 산업 표준을 따랐습니다. 프로덕션 라인으로 옮길 때 하드웨어만 교체하면 되도록 설계했습니다."

> "대부분의 포트폴리오가 공개 데이터셋을 쓰는데, 저는 직접 수집 프로세스를 설계해봤습니다. Light Trap, 편광, 카메라 파라미터 통제 같은 원칙을 구현하면서, 모델 성능이 사실 데이터 수집 단계에서 90% 결정된다는 걸 체감했습니다. 회사의 실제 문제도 공개 데이터셋이 없는 경우가 대부분이라, 이 경험이 직접 적용 가능하다고 생각합니다."

### 7-3. 왜 직접 수집이 차별점인가
- 대부분 포트폴리오는 공개 데이터셋(MVTec AD 등)만 사용
- "데이터 수집 프로세스를 설계해본 사람"은 드묾
- 실제 회사는 자사 도메인 공개 데이터셋이 거의 없음 → 즉전력
- ML은 80% 데이터, 20% 모델 (업계 통념) — 데이터 병목 이해 어필
