# Station1 (입고검사) 개발 일지

## 프로젝트 개요

- **공정**: 입고검사 — 빈 2% 음료 페트병의 외관 결함 검출
- **모델**: Anomalib PatchCore (비지도 이상탐지)
- **백본**: Wide ResNet-50-2 (ImageNet 사전학습)
- **검출 대상**: 보드마카 표식, 이물질(흰/유색 종이), 스크래치

## 3단계: 학습 파이프라인 시행착오

### 3-1. 초기 접근 (커스텀 구현)

**시도한 방식**:
- `cv2.imread` + 수동 ImageNet 정규화로 전처리
- 모델 직접 호출(`model(tensor)`)로 추론
- 자체 시각화 로직 (히트맵 + 마스크 직접 생성)

**문제점**:
- Anomaly Map이 부정확 (전체 파란색 또는 엉뚱한 영역 빨강)
- Pred Mask가 결함이 아닌 배경에 그려짐
- 학습 시 Anomalib 자동 생성 시각화와 **완전히 다른 품질**

**시도한 개선 (모두 효과 없음)**:
1. 퍼센타일 기반 마스크 (상위 5%)
2. Min-Max 정규화 후 0.5 기준
3. 상대 임계값 + 절대 임계값 조합
4. PostProcessor threshold 수동 덮어쓰기

### 3-2. PostProcessor 이슈 발견

Anomalib 학습 중 계산된 threshold가 실제 점수 분포와 맞지 않음:
```
image_threshold = 26.37
실제 정상 raw 점수: 31 ~ 47
→ 모든 이미지가 NG로 포화
```

PostProcessor를 우회하여 raw 점수로 직접 판정을 시도했으나,
**시각화는 여전히 Anomalib이 학습 때 만든 것과 다름**.

### 3-3. 최종 해결: Engine.predict() 공식 API 채택

**핵심 코드**:
```python
model = Patchcore()
engine = Engine(...)
predictions = engine.predict(
    model=model,
    dataset=dataset,
    ckpt_path=args.model,  # ← 이 인자가 핵심!
)
```

**결과**:
- 가중치 정상 로드
- Anomalib 공식 전처리 적용
- **학습 시 저장된 시각화와 100% 동일한 품질**

## 4단계: 최종 성능 비교 (Engine.predict 방식)

### 동일한 방법으로 두 데이터셋 테스트한 결과

| 항목 | 1차 데이터 (4/17) | 2차 데이터 (4/20) |
|---|---|---|
| AUROC | 0.958 | 1.0 |
| 학습 F1 | 0.8421 | 0.7027 |
| 자동 threshold | 36.33 | 39.57 |
| 정상 점수 범위 | **0.15 ~ 0.30** (좁음) | 0.29 ~ 0.46 (넓음) |
| 불량 점수 범위 | 0.40 ~ 1.0 | 0.48 ~ 0.99 |
| **실전 정확도** | **94%** (47/50) | **88%** (44/50) |
| 놓친 불량 | 3장 (38, 39, 40) | 3장 (41, 42, 44) |

### 1차 데이터 (4/17) 상세 판정

```
정상 1~30:    모두 OK ✅ (점수 0.15 ~ 0.30)
불량 31~35:   모두 NG ✅ (점수 1.0) — 파이리 강한 결함
불량 36~40:   2 NG / 3 OK 오판 ⚠️ (점수 0.40 ~ 0.57) — 작은 흰 종이
불량 41~45:   모두 NG ✅ (점수 0.70 ~ 0.78) — 보드마카
불량 46~50:   모두 NG ✅ (점수 0.66 ~ 0.70) — 스크래치

정확도: 47/50 = 94%
```

### 2차 데이터 (4/20) 상세 판정

```
정상 1~30:    모두 OK ✅ (점수 0.29 ~ 0.46)
불량 31~40:   모두 NG ✅ (점수 0.66 ~ 0.99) — 파이리 강한 결함
불량 41~50:   7 NG / 3 OK 오판 ⚠️ (점수 0.48 ~ 0.69) — 미세 결함

정확도: 44/50 = 88%
```

### 주요 인사이트

#### 1. 1차 데이터가 오히려 정확도 높음
```
예상: 통제 환경(2차)이 더 좋을 것
결과: 1차가 94%, 2차가 88%
```

**이유 추정**:
- 1차 데이터는 **같은 시각, 같은 장소에서 연속 촬영**되어 정상 내 점수 분포가 매우 좁음 (0.15~0.30)
- 2차 데이터는 **시각이 분산** (15:37 ~ 15:50, 16:43 ~ 16:50)되어 조명 변동이 포함됨
- 데이터 일관성이 환경 통제보다 중요한 경우가 있음

#### 2. 두 데이터셋 공통 한계
- **미세한 흰 종이 이물질** 3장은 두 경우 모두 놓침
- 224x224 리사이즈 시 작은 이물질이 정보 손실
- PatchCore의 본질적 한계 (미세 결함 탐지의 어려움)

#### 3. Anomaly Map과 Pred Mask 품질
- 두 데이터셋 모두 **Engine.predict() 방식**에서는 정확한 시각화 생성
- 학습 시 저장된 Anomalib 공식 시각화와 동일한 품질

## 5단계: 기술 결정 내역

### 채택
1. **Anomalib PatchCore** 모델 (Wide ResNet-50-2 백본)
2. **`Engine.predict(ckpt_path=...)`** 공식 API
3. **Anomalib `PredictDataset`** 전처리
4. **F1-score 최대화 기반 임계값 자동 탐색**

### 폐기
1. 커스텀 전처리 → PredictDataset 사용
2. PostProcessor 우회 + raw 점수 → Engine.predict()로 통일
3. 퍼센타일/정규화 기반 직접 마스크 생성 → Anomalib PostProcessor 마스크 사용
4. 결함 유형 분류 (crack/contamination 등) → PatchCore는 이상 여부만 판정
